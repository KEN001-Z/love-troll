# Supabase integration

VYBE is a multi-page static site built with Vite. It uses the existing Supabase project `vhkzyasknygybugugjyl` in `eu-west-1`.

## Local development and deployment

1. Install dependencies with `npm install`.
2. Copy `.env.example` to `.env.local` and set `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`. The URL and publishable key are browser-visible values. Never use a service-role key or secret key here.
3. Run `npm run dev` during development and open the Vite URL it prints (normally `http://localhost:5173`). Do not use VS Code Live Server to open the source HTML directly: it does not resolve the Supabase package or inject the Vite environment variables. Run `npm run build` for a static deployment; the output is in `dist/`. Netlify builds use [netlify.toml](./netlify.toml) to run that command and publish `dist/`; do not publish the raw project root.
4. Configure the deployed origin and the `login.html`, `onboarding.html`, and `reset.html` paths in Supabase Authentication → URL Configuration. For local development, allow the Vite origins `http://localhost:5173/**` and `http://127.0.0.1:5173/**`. Configure the email templates/provider if email confirmation or password recovery messages need delivery.

Vite embeds `VITE_` variables in client assets at build time; configure `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY` as Netlify build environment variables before deploying. These are browser-visible values; never put a service-role key or secret key there. `.env.local` is ignored by Git.

## Google sign-in

Google sign-in is available on both the login and signup pages. Before users can use it, create a **Web application** OAuth client in Google Cloud, add the local and deployed site origins as authorized JavaScript origins, and add the callback URL shown in Supabase Authentication → Providers → Google as an authorized redirect URI in Google Cloud. Then enable Google in that Supabase provider settings page and enter the Google client ID and client secret there. Keep the client secret in Supabase; it does not belong in `.env.local` or browser code. Also allow the deployed `login.html` and `onboarding.html` redirect URLs in Supabase Authentication → URL Configuration. Signup with Google still requires users to confirm they are 18 or older and accept the VYBE terms before redirecting to Google.

The student-profile migration adds profile photos, bio, education details, optional interests and tags, and visibility settings. Profile IDs are the authenticated Supabase Auth user UUIDs; the profile page uses `auth.getUser()` to identify the signed-in owner and fetches that owner’s row by the same UUID. Other profile IDs come from persisted profile rows and are checked by the database RPC against the current authenticated user and visibility rules. Names come from saved profile data or the owner’s Auth display-name metadata; usernames are never generated from IDs. The checked-in migration defines a private `profile-media` bucket for profile photos and covers, accessible to the owner, a campus-visible audience, or a mutual match. Post and DM media are defined by the later chat/media migration and require that migration to be applied. The live Storage dashboard could not be inspected in this session.

The posts migration permits authenticated, onboarded users to publish text posts. RLS binds inserts, edits, and deletes to `auth.uid()` and does not let clients change moderation status or timestamps. Direct table reads hide other users' anonymous rows; the authenticated feed RPC returns no author ID or name for anonymous posts and does not reveal another user's name or profile link when their profile is private. It only returns profile links for campus-visible profiles. The RPC returns only published posts, ordered by `(created_at, id)`, and supports `all` and `anonymous` keyset-paginated queries. Moderation can mark a post `removed` through trusted database administration; no moderation UI or reporting workflow is included. Image/video posting requires the media migration, and ordered multi-photo posts, profile post retrieval, and posts-table Realtime require the complete post-feed migration above. Polls, reactions, comments, competitions, and trending are not implemented.

## App-wide presence

Authenticated pages load `app-presence.js`, which tracks each signed-in user on the existing private `community:presence` Realtime topic. The Community migration already defines the authenticated read and publish policies for this topic, so app-wide online status does not require a database migration. Presence subscribers keep users online across page navigation and allow a short disconnect grace period before displaying them as offline. The separate photo-only message behavior does require the migration listed above.

## User flow

Supabase Auth stores and refreshes browser sessions. If Supabase rejects a stored session (including an invalid refresh token), VYBE clears that project's local auth entries and asks the user to log in again; network errors are not treated as expired-session recovery. Login checks the authenticated user's existing profile before routing to the homepage or onboarding. Signup initializes a missing profile without overwriting an existing one and routes authenticated users to onboarding. Email confirmation is enabled in the connected project, so users must confirm their address before a session can be created; the confirmation link returns to onboarding. Email delivery and redirect allow-lists still need to be configured and verified for the deployed origin. Logout explicitly revokes the current device's session, waits for Supabase to finish, and verifies the local session is cleared before leaving protected pages. If the server cannot confirm revocation but local sign-out succeeds, the user is informed rather than shown a success-shaped fallback. Onboarding choices and the current step are upserted as draft progress on each answer and navigation, then marked complete only after the final save succeeds and the user is redirected to the homepage. Returning users reload the saved answers and resume at the saved question.
